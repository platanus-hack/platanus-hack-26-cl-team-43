Quien compra no puede comprobar qué le sirven: si el modelo es el declarado, si está degradado o si el proveedor agrega instrucciones propias delante de su pedido.

Las certificaciones no lo cubren. SOC 2 e ISO 27001 revisan procesos de la empresa. Y una evaluación de seguridad vale para unos pesos y una configuración: si no se verifica qué se sirve, no cubre lo desplegado.

Una ficha por corrida, con lo declarado y lo medido.

cachai scan le manda el mismo juego de pruebas a cada endpoint y a una referencia. Cada dato de la ficha dice si lo declara el proveedor (E1) o si se midió desde afuera (E2).

Tokens de prompt de sobra E2

Compara los tokens de prompt de mensajes mínimos contra la referencia. Un excedente constante es la firma de un prompt oculto.

Exactitud E2

Tareas con respuesta calculable, a temperatura 0, comparadas con la referencia con el test exacto de Fisher.

Tool calls válidas E2

Una herramienta con esquema estricto. Cuenta cuántas llamadas lo cumplen.

Secreto del system prompt E2

Mide si el endpoint filtra el secreto cuando se lo piden, con un canario y un juez determinista.

Confiabilidad E2

Errores y latencia mediana de cada endpoint durante la corrida.

Lo declarado E1

Cuantización y precio, tal como los publica cada proveedor en la API de OpenRouter.

Pruebas que el proveedor no puede reconocer.

El juego de pruebas se genera con una semilla nueva en cada auditoría. La semilla queda en la ficha junto con el SHA-256 de las respuestas crudas, para que cualquiera pueda volver a correr la misma auditoría.

En la demo, el villano es un proveedor tramposo propio: un proxy que agrega un prompt oculto, desvía parte del tráfico a un modelo más barato y se porta bien cuando reconoce los prompts de una auditoría pública. La auditoría de prompts fijos no lo marca; la ciega sí.

Tres niveles de evidencia, siempre a la vista.

NivelQué esEjemplo
E1, declaradoLo afirma el proveedorCuantización, política de retención
E2, medidoLo medimos desde afuera, con método y muestraTokens de sobra, exactitud, tool calls
E3, atestadoEvidencia criptográfica verificablePesos medidos dentro de un TEE

Hoy el código cubre E1 y E2.

Para quién. Equipos que ya gastan en tokens de modelos abiertos a través de varios proveedores y tienen agentes en producción. Lo usa quien elige proveedor, para decidir a cuál mandarle tráfico y a cuál sacarlo.

Quién paga. Quien compra los tokens, no quien los vende. Así el auditado no financia su propia auditoría.

Qué no promete.

«Sin desviación detectada» no significa «es el mismo modelo». Cada dato de la ficha dice si está declarado por el proveedor o medido desde afuera.
No certifica privacidad. Desde afuera no se puede probar que un proveedor no mire ni guarde los datos.
«Distinguible de la referencia» no es una acusación. Puede deberse a la plantilla, al parser o a la cuantización.
